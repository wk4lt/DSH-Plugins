## P1

### BUG-001：同步可能静默覆盖本地修改

- 状态：已复现，待修复。
- 位置：`plugins/dsh-remote/lib/sync.js:40`、`:144`、`:236`。
- 原因：使用文件大小和秒级时间戳判断内容相等，没有验证字节内容。
- 复现：基线时间戳为 100，两端分别修改为大小相同、时间戳均为 200 的不同内容；执行拉取，冲突数为 0，本地内容被远端覆盖。
- 建议：完善内容校验及同步基线，覆盖拉取、推送和单文件自动推送的冲突判断。

### BUG-002：编辑截断的大文件会丢失尾部内容

- 状态：已通过客户端测试框架复现，待修复。
- 位置：`plugins/dsh-remote/lib/client.js:3058`、`:3063`、`:3099`。
- 原因：预览只读取前 256 KB，但编辑入口没有检查 `data.truncated`，保存时覆盖整文件。
- 复现：打开 300,000 字节文本文件，编辑预览并保存；提交的内容仅剩 262,148 字节。
- 建议：禁止编辑截断预览，或在编辑前完整读取并校验文件。

### BUG-003：下载文件可以写出本地映射目录

- 状态：已在 Windows 上通过模拟 SSH 复现，待修复。
- 位置：`plugins/dsh-remote/lib/routes-fs.js:231`。
- 原因：远端路径片段直接传给本地 `path.join()`，没有校验最终写入位置；POSIX 文件名中的反斜杠会被 Windows 当作路径分隔符。
- 复现：映射目录为本地 `checkout`，下载 Linux 远端 `/project/..\outside.txt`，接口返回 200，实际写入 `checkout` 的上级目录。
- 建议：校验路径片段和最终目标位置，同时检查符号链接及其他下载入口。

### BUG-004：`rw_push` 缺少沙箱权限检查

- 状态：已通过模拟 SSH 复现，待修复。
- 位置：`plugins/dsh-remote/lib/index.js:2281`。
- 复现：沙箱策略服务返回 `read-only`，在映射 checkout 新建文件后执行 `rw_push`；上传成功，远端文件被创建。
- 建议：在传输前执行统一权限检查，并明确预览与实际写入的处理规则。

### BUG-005：`rw_move` 没有检查目标路径权限

- 状态：已通过模拟 SSH 复现，待修复。
- 位置：`plugins/dsh-remote/lib/index.js:2650`。
- 原因：只对源路径调用 `requireRemoteSandbox()`。
- 复现：`workspace-write` 会话的远端工作区为 `/project`，将 `/project/a.txt` 移至 `/outside/a.txt`，操作成功。
- 建议：分别验证最终解析后的源路径和目标路径。

### BUG-006：沙箱策略解析异常后回退为全部权限

- 状态：已通过模拟 SSH 复现，待修复。
- 位置：`plugins/dsh-remote/lib/index.js:1671`。
- 原因：策略服务抛异常后落入配置回退；默认 `inherit` 最终变为 `danger-full-access`。
- 复现：令 `sandboxPolicy.resolve()` 抛异常，调用 `rw_write_file` 仍成功创建远端文件。
- 建议：区分没有策略服务与已有策略解析失败，解析失败时拒绝写入。

### BUG-007：会话端口转发使用另一台活动主机

- 状态：已通过两台模拟 SSH 服务器复现，待修复。
- 位置：`plugins/dsh-remote/lib/index.js:1040`、`:2900`。
- 原因：`rw_forward` 使用全局活动连接和 `store.currentId`，没有使用调用会话绑定的主机。
- 复现：会话映射到 A，切换全局活动主机为 B，再从 A 会话创建转发；B 收到新连接，转发记录的 `machineId` 为 B。
- 建议：让转发的创建、查询、移除和恢复遵循明确的主机归属。

### BUG-008：无法解析的会话 ID 回退到活动主机

- 状态：已通过模拟 SSH 复现，待修复。
- 位置：`plugins/dsh-remote/lib/index.js:1496`。
- 原因：请求携带 `sessionId` 但无法找到 cwd 时，继续进入全局活动主机回退分支。
- 复现：选择活动主机后，用不存在的 `sessionId` 请求 `/dsh-remote/read`，返回 200 和远端文件内容。
- 影响：写入及其他文件接口也共用此绑定解析函数。
- 建议：请求指定会话但无法解析时直接拒绝，只有未提供会话上下文的请求才能使用活动主机。

## P2

### BUG-009：Windows 远端工作区子路径被错误拒绝

- 状态：已通过函数级检查复现，待修复。
- 位置：`plugins/dsh-remote/lib/remote-sandbox.js:65`。
- 原因：Windows 路径归一化后使用反斜杠，但子路径判断拼接正斜杠。
- 复现：`workspace-write` 下检查工作区 `D:\project` 内的 `D:\project\src\app.js`，结果为拒绝。
- 建议：统一路径比较形式，覆盖 Windows 驱动器和 UNC 路径。

### BUG-010：映射模式单文件下载到托管镜像而非 checkout

- 状态：已通过模拟 SSH 复现，待修复。
- 位置：`plugins/dsh-remote/lib/index.js:2826`。
- 原因：`rw_download` 的默认目标调用 `mirrorDirFor()`，忽略绑定提供的 `b.mirrorDir`。
- 复现：将已有 checkout 映射到远端，执行未指定 `localPath` 的 `rw_download`；工具报告下载成功，文件出现在托管镜像，checkout 中没有该文件。
- 建议：默认目标遵循当前绑定，并结合 BUG-003 校验目标路径。

### BUG-011：`rw_sync` 的深度参数未传入底层

- 状态：已通过模拟 SSH 复现，待修复。
- 位置：`plugins/dsh-remote/lib/index.js:2238`、`plugins/dsh-remote/lib/sync.js:70`。
- 原因：调用方传递 `depth`，底层读取 `maxDepth`，实际一直使用默认值 8。
- 复现：设置 `depth: 16`，第 10 层文件仍未下载；提示却要求继续提高已经设为 16 的深度。
- 建议：统一参数名，并验证上调、下调深度均生效。

### BUG-012：同步读写失败被静默吞掉

- 状态：目录读取失败已通过函数级检查复现；文件读写错误吞掉的分支已静态确认。待修复。
- 位置：`plugins/dsh-remote/lib/sync.js:83`、`:166`、`:264`。
- 原因：目录读取失败被转为空列表，文件传输失败未进入结果中的错误统计。
- 复现：令远端 `readdir()` 抛出权限错误，同步正常返回 0 个文件，结果没有错误信息。
- 建议：区分空目录与读取失败，汇总传输错误，并在工具结果中报告部分失败或整体失败。
